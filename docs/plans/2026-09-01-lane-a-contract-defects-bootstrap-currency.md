## Appendix A — the approved bootstrap contract (closes proposal-review finding F008)

Johnny approved this spec 2026-09-01; it is reproduced here in full so implementer and reviewer share one oracle (r1-F003).

**`bootstrap` object** — OPTIONAL key under `schema_version` 1; when present, ALL FOUR child fields required; `additionalProperties: false`:

```json
"bootstrap": {
  "type": "object",
  "required": ["clodex_version", "derived_at", "repo_fingerprint", "inspected"],
  "additionalProperties": false,
  "properties": {
    "clodex_version":   {"type": "string"},
    "derived_at":       {"type": "string"},
    "repo_fingerprint": {"type": "string"},
    "inspected": {"type": "array", "items": {
      "type": "object",
      "required": ["marker", "present", "value"],
      "additionalProperties": false,
      "properties": {
        "marker":  {"type": "string"},
        "present": {"type": "boolean"},
        "value":   {"type": ["string", "null"]}
      }}}
  }
}
```

Formats (documented in descriptions; enforced by `bootstrap_check.py`, since the repo's validator ignores `pattern`): `clodex_version` = `MAJOR.MINOR.PATCH` copied from `skills/clodex/VERSION`; `derived_at` = `YYYY-MM-DD`; `repo_fingerprint` = `sha256:<64 lowercase hex>`.

**MARKERS vocabulary** — one fixed tuple in `inspect_repo.py`, feeding BOTH the `inspected` list and the fingerprint from a single probe. Existence markers (boolean, `value: null`), in this order:
`package.json`, `pyproject.toml`, `Makefile`, `Dockerfile`, `docker-compose.yml`, `tox.ini`, `vercel.json`, `railway.json`, `fly.toml`, `.nvmrc`, `.tool-versions`, `.python-version`, `go.mod`, `Cargo.toml`, `requirements.txt`, `setup.py`, `tests/`, `.github/workflows`, `.gcloudignore`, `.dockerignore`, `.vercelignore`, `.npmignore`, `CHANGELOG.md`, `js-lockfile` (present when ANY of `package-lock.json`/`yarn.lock`/`pnpm-lock.yaml` exists).
Value markers (present + string value):
`package.json#scripts` (sorted script key names, comma-joined), `package.json#engines` (sorted `name=constraint`, comma-joined), `.github/workflows#files` (sorted filenames, comma-joined), `pyproject.toml#requires-python` (the literal constraint).
Excluded by design: `profile.commands.*` (the F008 circularity — first-run computes the fingerprint before a profile exists), file contents, lockfile hashes.

**Canonical serialization** (fingerprint input): one line per marker in vocabulary order, `<marker>\t<0|1>\t<value-or-empty>`, lines joined with `\n`, UTF-8-encoded, sha256 over the bytes, rendered `sha256:<hex>`. The vocabulary (names and order) is part of the contract: changing it is a behavior change requiring a MINOR `VERSION` bump — and `bootstrap_check.py` decides the skill-moved verdict (minor-version compare) BEFORE comparing fingerprints, so vocabulary growth in a minor release re-derives rather than false-firing "repo moved".

**Six-question verdict table** (order fixed; run AFTER §3's profile step):
1. No profile at all → `first-run` (defer to §3; not a failure).
2. `schema_version` outside the schema's enum → `re-derive` (never partial repair; never rewrite the version down).
3. `bootstrap.clodex_version` minor ≠ `skills/clodex/VERSION` minor → `re-derive`; in a linked worktree: recorded, not enforced.
4. Recomputed fingerprint ≠ `bootstrap.repo_fingerprint` → `re-derive` in the main checkout; recorded, not enforced in a linked worktree.
5. `bootstrap.inspected` empty or not covering every marker the recompute knows → `re-derive`.
6. Linked worktree with `.clodex/profile.json` untracked → `stop` (the original check 7, unchanged).

Exact-key enforcement: because the repo's profile validator deliberately ignores `additionalProperties`, `bootstrap_check.py` additionally verifies the bootstrap object and each `inspected` item carry EXACTLY the approved keys, and refuses (`re-derive` verdict with the offending key named) otherwise (r2-F006).
